# Stochastic Thinking & Random Walks(Lec04 & 05)

_"결정론적(Deterministic) 방정식으로 완벽하게 예측할 수 없는 세상. 다음 발걸음이 어디로 향할지 모르는 이 '불확실성'을, 우리는 어떻게 코드라는 통제된 상자 안에 가둬둘 것인가? 이것이 시뮬레이션의 본질이다."_

## Theme 1. 결정론의 한계와 확률적 사고 (Stochastic Thinking)

뉴턴 역학처럼 '모든 원인이 명확한 결과를 낳는다'는 결정론적 사고는 버려라. 세상은 양자역학(코펜하겐 해석)처럼 완벽히 예측 불가능한 확률적(Stochastic) 모델로 돌아간다 

- 주식 시장의 폭락, 액체 속 분자의 움직임, 혹은 술 취한 사람의 걸음걸이(Drunkard's Walk)가 그 예시다 

- **컴퓨터 공학의 대답:** "수식으로 정확한 답을 낼 수 없다면? 컴퓨터의 무식하고 폭력적인 연산력을 빌려 **직접 수만 번 시뮬레이션(Simulation)** 해버리면 된다."

## Theme 2. 불확실성을 통제하는 객체지향(OOP)의 3기둥

이 복잡한 무작위성을 딕셔너리와 리스트로 대충 묶어 스파게티 코드로 짜면 데이터가 뒤엉켜 무조건 버그가 터진다. 완벽한 시뮬레이션을 위해서는 역할을 3개의 클래스(Class)로 엄격하게 분리(Abstraction)해야 한다 

(1) `Location` (위치) : 데이터 무결성의 수호자

- 현재의 좌표 `(x, y)` 정보를 담는 객체다.
- **설계 원칙:** 이 객체는 한 번 생성되면 절대 내부 값을 바꿀 수 없는 **'불변(Immutable)'** 타입으로 설계해야한다 . 누군가 코드 밖에서 좌표를 마음대로 조작해버리면 시뮬레이션의 물리 법칙 자체가 붕괴된다. 이동할 때는 기존 좌표를 덮어쓰는 게 아니라, 계산된 좌표를 가진 **아예 새로운 Location 객체를 반환**하게 만들어야 한다 

(2) `Drunk` (주체) : 행동의 분화

- 실제로 걷는 주체다. 여기서 상속(Inheritance)의 진가가 드러난다
- 기본 `Drunk`를 부모로 두고, 동서남북 확률이 동일한 `UsualDrunk`, 북쪽으로 치우쳐서 걷는 `MasochistDrunk` 등을 자식 클래스로 파생시켜야 한다 메인 시뮬레이션 코드는 단 한 줄도 뜯어고칠 필요 없이, 걷는 놈만 갈아 끼우면 알아서 돌아간다.

(3) `Field` (공간) : 가변적 연결망

- `Drunk` 객체(Key)와 그들의 현재 `Location`(Value)을 매핑하는 딕셔너리(`{}`)를 품고 있는 객체다 

- 사람들이 한 걸음씩 걸을 때마다 위치가 계속 업데이트되어야 하므로, 필연적으로 내용물이 변하는 **'가변(Mutable)'** 객체로 설계된다

📌 Theme 3. ⚠️ 실전의 생명줄: Sanity Check (논리적 지뢰 제거)

실무에서 가장 많이 무너지는 지점이다. 코드를 다 짰다고 곧바로 10만 번짜리 시뮬레이션을 무지성으로 돌려버리는 건 하수 중의 하수다.

- **Sanity Check (제정신인지 확인하기):** 코드를 검증하려면, 우리가 **정답을 이미 완벽하게 알고 있는 아주 단순한 케이스**를 먼저 넣어봐라 
- _예: 0번 걸었을 때 원점과의 거리가 0이 나오는가? 1번 걸었을 때 거리가 1이 나오는가?_ 
- 여기서 기대한 값이 안 나오면, 10만 번 돌린 결과는 분석할 가치조차 없는 쓰레기 데이터다. 뼈대 로직부터 다시 잡아라.
